# TechnoRogue — Session Log

## 2026-07-25 — Mobile: Invisible Cards Fix

**Symptom:** Hand cards were invisible in the Expo combat screen (landscape).

**Root cause (layout, not data):** The data/re-render path was fine
(`Game` event → `GameContext` tick → re-render), and last session's
`handScrollView: { flex: 1 }` fix was intact. The real problem was the
vertical layout budget under the landscape lock:

- Cards were sized off width only (`CARD_H = CARD_W * 1.45` ≈ 160px).
- The combat screen is a vertical column with fixed-height enemy section
  (`minHeight: 180`), player bar, and action row. The hand area was `flex: 1`,
  so it only got *leftover* height.
- On the short landscape axis, the fixed sections consumed nearly all the
  height, collapsing the `flex: 1` hand area toward 0px. The horizontal
  ScrollView clipped the 160px cards to ~zero height → invisible.

**Fix (`app/combat.tsx`):**
- Size cards off the SHORT axis: `CARD_H = clamp(112, height*0.42, 160)`,
  `CARD_W = min(CARD_H/1.5, (width-32)/3.5, 110)`.
- `enemySection`: replaced `minHeight: 180` with `flexShrink: 1` so it yields
  space instead of starving the hand.
- `handArea`: added `flexShrink: 0` + `minHeight: CARD_H + 24` so the hand can
  never collapse below one full card row.

**Validation:** `pnpm --filter @workspace/techno-rogue-mobile run typecheck`
passes clean. (Note: `pnpm install` was required first — node_modules was absent.)

### CORRECTION — the layout fix was NOT the cause

On-device the cards were still invisible after the layout change. Root cause
was **React Compiler** (`app.json` → `experiments.reactCompiler: true`, plus
`babel-plugin-react-compiler`) interacting with the mutation-based `Game`
singleton:

- `useGame()` returns the same `Game` object every render.
- `player.hand` is mutated **in place** (`hand.push()` in `DeckSystem`), so its
  array **reference never changes**.
- React Compiler memoizes `player.hand.map(...)` keyed on that stable reference.
- On mount the hand is empty (`startCombat()` runs in a post-mount effect). RC
  caches the empty render; the later draw mutates the same array without a new
  reference, so the memo never invalidates → cards never appear.
- Fits "only cards invisible": HP/energy are primitives, `enemies` gets a fresh
  array via `slice()`, but `hand` mutates in place.

Verified by inspecting the compiled iOS bundle: `CombatScreen` opened with
`_reactCompilerRuntime.c(104)` (a memo cache) before the fix.

**Fix:** add the React Compiler opt-out directive `'use no memo';` to the three
screens that read the mutable singleton — `app/combat.tsx`, `app/map.tsx`,
`app/index.tsx`. Re-inspected the bundle: none are memoized now.

The earlier layout change is kept — it's a genuine landscape improvement — but
it was not the fix.
